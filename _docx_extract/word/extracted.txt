Distress-Intelligence Operating System
DISTRESS-INTELLIGENCE OPERATING SYSTEM
Complete Blueprint, Scoring Models & Operating Documentation — v1.1 (adds Detection Layer platform directory)
Purpose: one research engine that detects financial distress across asset classes, scores every opportunity, and outputs exactly one decision: BID UNIT, WHOLESALE, CLEANOUT, RUNNER-SCRAP, or PASS.
Core constraint the system is built around: ~$10 of starting capital. Every deal must be structured as revenue-share, assignment, or pay-after-sale. Nothing requires upfront cash.
1. System Architecture
SOURCES → INGEST → LEAD DATABASE → 4 SCORING ENGINES → MASTER ROUTER      → CRM PIPELINE → MONETIZATION ARMS → DEAL LEDGER → CALIBRATION LOOP                              ↕              HUMAN NETWORK (runners, crews, buyers, partners)
SOURCES — public records, auction/listing photos, sold-price comps, skip-trace vendor, free-section monitors, social signals. All ingestion is automated on a schedule (cron / n8n-style automation). See Section 3 for the full platform directory.
LEAD DATABASE — one table of leads, each tagged by asset class (storage / real estate / estate / commercial / junk), distress signal, source, owner identity, and pipeline stage.
SCORING ENGINES — four deterministic scorers (Sections 4–7). Same inputs always produce the same score; the AI does extraction and research, the math is fixed.
ROUTER — applies thresholds, decides the play, rejects deals (Section 8).
PIPELINE — lead moves through fixed stages with exit criteria (Section 9).
MONETIZATION ARMS — scrap floor (same-day cash), resale margin, assignment fees, referral fees, consignment splits.
LEDGER — every dollar in and out per deal (Section 11).
CALIBRATION LOOP — predicted vs. realized results feed back into weights and thresholds (Section 13).

Category probabilities (starting values, calibrate per Section 13): quality tool chest 0.7 · golf clubs 0.6 · electronics 0.5 · furniture 0.45 · sealed retail stock 0.65 · mystery boxes 0.2.
Worked example: Snap-on chest 0.7×$800=$560 · clubs 0.6×$120=$72 · TV 0.5×$150=$75 · scrap floor $85 → gross $792 − $150 cleanout/dump = EV $642 → bid ceiling = EV × 0.45 = $290. If bidding passes $290, walk away.

7. Junk / Scrap Cash Engine (runner fuel)
Purpose: same-day cash that pays the physical network so nothing else needs upfront money. Gate rule: RUN only if scrap_estimate ≥ 1.5 × (runner payout + dump fees) AND pickup is inside the service radius. Sources: junk-removal requests ("free removal"), free-section curb alerts, overflow from cleanouts and units. Anything resellable is pulled before the scrap run. Scrap yards pay same day; runner is paid same day from that cash.
8. Master Router
New lead  ├─ Is it a storage unit?        → Storage Engine → BID / CONDITIONAL / WATCH / PASS  ├─ Is it a property?            → RE Engine      → CONTRACT / OPTION / PASS  ├─ Is it an estate/household?   → Estate Engine  → CLEANOUT / HYBRID / PASS  ├─ Is it bulk junk/metal?       → Scrap gate     → RUN / PASS  └─ Multi-asset (e.g., owner has house + unit + car)?        → score each, then price as a PACKAGE — bundle discount to owner,          combined EV usually beats summed individual EVs
Router rules: (1) a PASS at any tier can be overridden only by a hard-number reason logged in the lead record; (2) every WATCH lead auto-re-scores when its timeline event fires (auction date, foreclosure date, house closing); (3) anything marginal goes to scrap gate check before final pass — a $90 scrap floor can rescue a mediocre unit.

11. Money Flow & Deal Ledger
All buyer payments route to the business account (WHOP PAYEMENT GATEWAY→ business checking as soon as volume justifies).
Owner/heir remittance goes out on delivery confirmation; runner/crew same day; your margin stays in the float.
Ledger fields per deal: deal_id · class · EV predicted · all costs (haul, dump, boost, fees) · gross · splits · realized margin · days to cash.
Expense float comes ONLY from scrap revenue — never from the $10 reserve.
Weekly reconciliation; any deal with realized margin < 25% of predicted gets a reason code for calibration.
13. Calibration Loop (how the system gets smarter)
Log predicted EV vs. realized result for every deal, per category. Monthly: compute error (MAPE). Rules:
Category MAPE > 30% → lower that category's probability and widen margin factor (bid multiplier 0.45 → 0.35) until error recovers.
Category consistently beats prediction → raise probability, tighten margin, bid more aggressively.
Any category with 3+ consecutive negative realized margins → auto-PASS category pending manual review.
Facility tiers re-ranked quarterly from realized resale ratios.
Dead-reason codes reviewed monthly — if "overbid at auction" dominates, raise bid discipline; if "no reply" dominates, fix outreach scripts.
